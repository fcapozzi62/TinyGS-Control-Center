# Contributing

Thank you for your interest. TinyGS Control Center is experimental and is not affiliated with official TinyGS.

- Start with an issue describing the desired behavior, constraints and hardware where applicable.
- Keep pull requests small, explain the design and include or update automated tests.
- Use feature branches. Avoid committing local data, passwords, MQTT credentials, flash dumps or station-specific secrets.
- Write code and public documentation in English. Be precise about which radio and firmware versions have actually been tested.
- Report security issues privately to the repository maintainer rather than sharing credentials or exploitable details in a public issue.
